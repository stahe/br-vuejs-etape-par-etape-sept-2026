    // =========================================================================
// vite.config.ts - a configuração do Vite, compartilhada por TODOS os exemplos.
// -------------------------------------------------------------------------
// O Vite é ao mesmo tempo:
//   - um servidor de desenvolvimento (npm run dev): compila na hora os
//     arquivos .vue e .ts solicitados pelo navegador e recarrega a página
//     (ou apenas o componente modificado) a cada salvamento;
//   - uma ferramenta de build (npm run build): gera, em dist/,
//     arquivos .js e .css otimizados para colocar em um servidor web.
//
// Cada exemplo é uma pequena aplicação independente, com seu próprio
// index.html: 01-first-application/index.html, 02-reactivity/index.html...
// Um único servidor Vite atende a todos: http://localhost:5173/ exibe o
// sumário (index.html desta pasta), http://localhost:5173/01-first-application/
// o primeiro exemplo, etc.
// =========================================================================

import { existsSync, readdirSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import { resolve } from 'node:path';
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

const root = fileURLToPath(new URL('.', import.meta.url));

// as pastas dos exemplos: aquelas cujo nome começa com dois dígitos
const examples = readdirSync(root).filter((d) => /^\d\d-/.test(d) && existsSync(resolve(root, d, 'index.html')));

export default defineConfig({
  // o plugin que ensina o Vite a compilar arquivos .vue
  plugins: [vue()],

  server: {
    port: 5173,
    // o PROXY: qualquer requisição do navegador para /api/... é encaminhada pelo
    // Vite ao servidor JSON do RdvMedecins (porta 8080) e a resposta volta
    // ao navegador. Para o navegador, página e API têm assim a MESMA origem
    // (http://localhost:5173): sem CORS para configurar, e o cookie do
    // token JWT trafega normalmente (veja o capítulo sobre a caixa-preta).
    proxy: {
      '/api': 'http://localhost:8080',
    },
  },

  // npm run build: uma página HTML de entrada por exemplo, mais o sumário
  build: {
    rollupOptions: {
      input: Object.fromEntries([
        ['contents', resolve(root, 'index.html')],
        ...examples.map((d) => [d, resolve(root, d, 'index.html')]),
      ]),
    },
  },
});
    • linha 31: a extensão que instrui o [Vite] a compilar os arquivos [.vue]. Um navegador não consegue ler um arquivo [.vue]: quando ele solicita um, o [Vite] o converte na hora em um [JavaScript] padrão;
    • linha 34: a porta do servidor de desenvolvimento;
    • linhas 40–41: o proxy, que só será usado a partir do Exemplo 17: toda requisição do navegador a um endereço que comece por [/api] é encaminhada ao servidor JSON [RdvMedecins], na porta 8080. Voltaremos a isso;
    • Linhas 27 e 46–53: o [npm run build] precisa conhecer todas as páginas de entrada da aplicação. Fornecemos a ele o índice e o arquivo [index.html] de cada pasta cujo nome começa com dois dígitos.

    <!--
  =========================================================================
  01-first-application/src/App.vue - a first component
  -------------------------------------------------------------------------
  A .vue file (Single File Component) groups the three facets of a
  component:
    - <script setup>: the data and the code of the component (TypeScript);
    - <template>    : the HTML to display, with {{ ... }};
    - <style>       : its CSS (here "scoped": it only applies to it).
  =========================================================================
-->
<script setup lang="ts">
import { ref } from 'vue';

// dados "comuns": o template pode exibi-los
const title = 'Welcome to Vue.js';
const languages = ['TypeScript', 'HTML', 'CSS'];

// ref(...): um dado REATIVO. Quando seu valor (.value) muda, o Vue
// atualiza AUTOMATICAMENTE os pontos da página que o exibem
const counter = ref(0);
const time = ref(new Date().toLocaleTimeString());

// uma função chamada pelo botão do template
function increment(): void {
  counter.value++;
  time.value = new Date().toLocaleTimeString();
}
</script>

<template>
  <div class="container py-4">
    <!-- {{ expression }}: o valor da expressão, inserido na página -->
    <h1 class="h3">{{ title }}</h1>
    <p>This page is built in the browser, by Vue.js, from three files: index.html, main.ts and App.vue.</p>
    <p>It is written in {{ languages.join(', ') }} ({{ languages.length }} languages).</p>

    <!-- @click: a função a chamar em um clique (veja o exemplo 04) -->
    <button class="btn btn-primary" @click="increment">Click me</button>
    <!-- no template, sem .value: o Vue "desembrulha" os refs sozinho -->
    <p class="mt-3 counter">You clicked {{ counter }} times (last click: {{ time }}).</p>
  </div>
</template>

<style scoped>
/* "scoped": esta regra se aplica apenas aos elementos DESTE componente */
.counter {
  font-weight: bold;
  color: #0d6efd;
}
</style>

    Um arquivo [.vue] (Single File Component, ou SFC) reúne as três facetas de um componente:

    • linhas 12–29: o código do componente, em [TypeScript] ([lang="ts"]). Com [setup], todas as variáveis e funções declaradas no nível superior do script ficam diretamente utilizáveis no template;
      • linhas 16–17: dois dados comuns;
      • linha 21: [ref(0)] cria um dado reativo com valor inicial 0. Seu valor é lido e modificado por meio de sua propriedade [value]. Quando ele muda, o [Vue.js] atualiza todos os pontos da página em que ele é exibido;
      • linhas 25–27: uma função que modifica dois dados reativos. Ela não altera a página: o [Vue.js] se encarrega de atualizá-la;
    • linhas 31–43: o HTML do componente:
      • linha 34: a sintaxe [{{ expression }}] (os “bigodes”) insere na página o valor de uma expressão [TypeScript]. Ela é escapada: se [title] contivesse [<b>], [<b>] seria exibido sem que a tag fosse interpretada;
      • linha 36: a expressão pode ser qualquer coisa: uma chamada de método, um cálculo;
      • linha 39: o clique no botão chama a função [increment] (veja o exemplo 04);
      • linha 41: no template, escreve-se [counter], não [counter.value]: o [Vue.js] “desembrulha” automaticamente o [ref];
    • linhas 45–51: o CSS do componente. Com [scoped], suas regras se aplicam apenas aos elementos deste componente: o [Vite] adiciona um atributo único aos elementos dele ([data-v-xxxx]) e o inclui nos seletores.

    <!--
  =========================================================================
  02-reactivity/src/App.vue - ref, reactive, computed, watch
  -------------------------------------------------------------------------
  A small calculator of prices including VAT:
    - ref      : a simple reactive value (a number, a string...);
    - reactive : a reactive OBJECT (all its properties are reactive);
    - computed : a value COMPUTED from other ones, recomputed
                 automatically when they change;
    - watch    : code executed when a value changes (an "effect").
  =========================================================================
-->
<script setup lang="ts">
import { computed, reactive, ref, watch } from 'vue';

// ref: seu valor é lido e escrito por meio de .value (no código TypeScript)
const quantity = ref(1);

// reactive: um objeto, cujas propriedades são lidas e escritas diretamente
const item = reactive({
  label: 'Pen',
  priceExclVat: 2.5,
  vatRate: 20, // em %
});

// computed: nunca atribuído diretamente, sempre recalculado. O Vue sabe de quais
// dados ele depende (quantity, item.priceExclVat, item.vatRate):
// ele o recalcula quando um deles muda, e somente nesse caso
const totalExclVat = computed(() => quantity.value * item.priceExclVat);
const vatAmount = computed(() => (totalExclVat.value * item.vatRate) / 100);
const totalInclVat = computed(() => totalExclVat.value + vatAmount.value);

// um formatador de valores em euros, no estilo inglês (€1,234.50)
const euros = new Intl.NumberFormat('en-US', { style: 'currency', currency: 'EUR' });

// watch: a cada mudança do total com impostos, guardamos um registro
const history = ref<string[]>([]);
watch(totalInclVat, (newValue, oldValue) => {
  history.value.unshift(`${euros.format(oldValue)} -> ${euros.format(newValue)}`);
  history.value = history.value.slice(0, 5); // os 5 últimos
});

function reset(): void {
  quantity.value = 1;
  item.priceExclVat = 2.5;
  item.vatRate = 20;
}
</script>

<template>
  <div class="container py-4">
    <h1 class="h3 mb-3">Example 02 - reactivity</h1>
    <div class="row g-4">
      <div class="col-md-6">
        <div class="card p-3">
          <!-- v-model vincula um campo a um dado, nos dois sentidos (veja o exemplo 05) -->
          <label class="form-label">Item</label>
          <input v-model="item.label" class="form-control mb-2">
          <label class="form-label">Unit price excl. VAT</label>
          <input v-model.number="item.priceExclVat" type="number" step="0.1" min="0" class="form-control mb-2">
          <label class="form-label">Quantity</label>
          <input v-model.number="quantity" type="number" min="0" class="form-control mb-2">
          <label class="form-label">VAT rate</label>
          <select v-model.number="item.vatRate" class="form-select mb-3">
            <option :value="5.5">5.5 %</option>
            <option :value="10">10 %</option>
            <option :value="20">20 %</option>
          </select>
          <button class="btn btn-outline-secondary" @click="reset">Reset</button>
        </div>
      </div>
      <div class="col-md-6">
        <div class="card p-3">
          <h2 class="h5">{{ quantity }} x {{ item.label }}</h2>
          <table class="table mb-0">
            <tbody>
              <tr><td>Total excl. VAT</td><td class="text-end">{{ euros.format(totalExclVat) }}</td></tr>
              <tr><td>VAT ({{ item.vatRate }} %)</td><td class="text-end">{{ euros.format(vatAmount) }}</td></tr>
              <tr class="fw-bold"><td>Total incl. VAT</td><td class="text-end">{{ euros.format(totalInclVat) }}</td></tr>
            </tbody>
          </table>
        </div>
        <div class="card p-3 mt-3">
          <h2 class="h6">History of the total incl. VAT (watch)</h2>
          <ul class="mb-0">
            <li v-for="(line, i) in history" :key="i">{{ line }}</li>
          </ul>
        </div>
      </div>
    </div>
  </div>
</template>
    • linha 17: [ref] aceita um valor simples (número, string, booleano);
    • linhas 20–24: [reactive] torna reativo um objeto inteiro: cada uma de suas propriedades é reativa. Elas são lidas e escritas diretamente ([item.priceExclVat]), sem [.value];
    • linhas 29–31: [computed] define um valor calculado a partir de outros valores. O [Vue.js] memoriza os dados lidos durante o cálculo ([quantity], [item.priceExclVat]...) e só recalcula quando um deles muda. Nunca se atribui um valor a ele: ele é lido ([totalExclVat.value]);
    • linha 34: [Intl.NumberFormat], a ferramenta de formatação de números integrada ao [JavaScript]: [2.5] torna-se “€2.50”;
    • linhas 38–41: [watch] executa código sempre que um dado muda, recebendo o novo valor e o antigo. Ele serve para ações como salvar dados, enviar uma requisição ou escrever no armazenamento do navegador... Para exibir um valor derivado, preferimos o [computed];
    • linhas 43–46: basta modificar os dados; todos os campos, totais e o histórico são atualizados de acordo;
    • linhas 58–64: [v-model] liga cada campo a um dado, nos dois sentidos (veja o exemplo 05);
    • linha 77: no template, um [computed] é usado da mesma forma que um [ref], sem [.value];
    • linha 86: uma lista repetida para cada elemento do array [history] (veja o exemplo 03).

    <!--
  =========================================================================
  03-directives/src/App.vue - the basic directives
  -------------------------------------------------------------------------
  A DIRECTIVE is a special attribute of the template, prefixed by v-:
    - v-bind:attr="expr" (short form :attr="expr"): the value of an HTML
      attribute computed by an expression; :class and :style accept
      objects and arrays;
    - v-if / v-else-if / v-else: the element only exists in the page if
      the condition is true;
    - v-show: the element always exists, it is only hidden (display:none);
    - v-for="x in list": the element is repeated for each x, with a
      unique :key that allows Vue to follow each row.
  =========================================================================

  04-events/src/App.vue - reacting to the user's actions

  v-on:event="handler" (short form @event="handler"):

<script setup lang="ts">
import { ref } from 'vue';

interface Task {
  id: number;
  label: string;
  done: boolean;
}

const tasks = ref<Task[]>([
  { id: 1, label: 'Install Node.js', done: true },
  { id: 2, label: 'Read the chapter on events', done: false },
]);
const newTask = ref('');
const log = ref<string[]>([]);
let nextId = 3;

function trace(message: string): void {
  log.value.unshift(`${new Date().toLocaleTimeString()} ${message}`);
}

// chamado por @submit.prevent: o navegador NÃO envia o formulário ao
// servidor (sem recarregar a página), é o nosso código que age
function add(): void {
  const label = newTask.value.trim();
  if (label === '') {
    return;
  }
  tasks.value.push({ id: nextId++, label, done: false });
  trace(`added "${label}"`);
  newTask.value = '';
}

function remove(task: Task): void {
  tasks.value = tasks.value.filter((t) => t.id !== task.id);
  trace(`removed "${task.label}"`);
}

// $event: o evento nativo (aqui um MouseEvent), com suas coordenadas
function position(event: MouseEvent): void {
  trace(`click at (${event.offsetX}, ${event.offsetY})`);
}
</script>

      <input v-model="newTask" class="form-control" placeholder="new task" @keyup.esc="newTask = ''">
      <button type="submit" class="btn btn-primary">Add</button>
    </form>

    <ul class="list-group mb-3">
      <li v-for="t in tasks" :key="t.id" class="list-group-item d-flex align-items-center gap-2">
        <input v-model="t.done" type="checkbox" class="form-check-input" @change="trace(`“${t.label}”: ${t.done ? 'done' : 'to do'}`)">
        <span :class="{ 'text-decoration-line-through text-muted': t.done }" class="flex-grow-1">{{ t.label }}</span>
        <!-- um handler com um argumento: a tarefa DESTA linha -->
        <button class="btn btn-sm btn-outline-danger" @click="remove(t)">Delete</button>
      </li>
    </ul>

    <div class="area p-3 mb-3 rounded" @click="position($event)">Click in this area</div>

    <h2 class="h6">Log</h2>

    <!--
  =========================================================================
  06-validation/src/App.vue - validating a form in the browser
  -------------------------------------------------------------------------
  The errors are COMPUTED values: they are recomputed on each keystroke.
  They are not displayed right away (an empty form covered in red is
  unpleasant): only for a field already left ("touched"), or for
  all the fields after a submission attempt.

  Same rules as the RdvMedecins server ("Create a patient account" form):
  title in the list, first name and last name required (20 characters at most),
  login in lower case, password of at least 6 characters, confirmation.

  WARNING: this validation is only a COMFORT for the user (an
  immediate answer, without a round trip to the server). It protects
  nothing: anyone can send the server a request built by
  hand (curl...). The server therefore ALWAYS revalidates everything (see example 20).
  =========================================================================
-->
<script setup lang="ts">
import { computed, reactive, ref } from 'vue';

const TITLES = ['Mr', 'Mme', 'Melle'];
const LOGIN_FORMAT = /^[a-z0-9._-]{1,30}$/;
const PASSWORD_MIN = 6;

type Field = 'title' | 'firstName' | 'lastName' | 'login' | 'password' | 'confirmation';

const input = reactive<Record<Field, string>>({
  title: 'Mr',
  firstName: '',
  lastName: '',
  login: '',
  password: '',
  confirmation: '',
});

// os campos já abandonados pelo usuário (evento blur)
const touched = reactive(new Set<Field>());
const submitAttempted = ref(false);
const success = ref(false);

// o erro de cada campo ('' = sem erro), recalculado a cada tecla digitada
const errors = computed<Record<Field, string>>(() => ({
  title: TITLES.includes(input.title) ? '' : 'Choose a title from the list.',
  firstName: required(input.firstName, 'The first name') || maximum(input.firstName, 'The first name', 20),
  lastName: required(input.lastName, 'The last name') || maximum(input.lastName, 'The last name', 20),
  login:
    required(input.login, 'The login') ||
    (LOGIN_FORMAT.test(input.login.trim())
      ? ''
      : 'Unaccented lower-case letters, digits, dot, hyphen, underscore.'),
  password:
    required(input.password, 'The password') ||
    (input.password.length < PASSWORD_MIN ? `At least ${PASSWORD_MIN} characters.` : ''),
  confirmation: input.confirmation === input.password ? '' : 'The confirmation does not match the password.',
}));

const formValid = computed(() => Object.values(errors.value).every((e) => e === ''));

function required(value: string, name: string): string {
  return value.trim() === '' ? `${name} is required.` : '';
}
function maximum(value: string, name: string, max: number): string {
  return value.trim().length > max ? `${name} must not exceed ${max} characters.` : '';
}

// o erro a EXIBIR para um campo: somente se ele foi tocado, ou após
// uma tentativa de envio
function visibleError(field: Field): string {
  return touched.has(field) || submitAttempted.value ? errors.value[field] : '';
}

function send(): void {
  submitAttempted.value = true;
  success.value = formValid.value;
}
</script>

<template>
  <div class="container py-4" style="max-width: 640px">
    <h1 class="h3 mb-3">Example 06 - form validation</h1>
    <!-- novalidate: the browser's own validation is disabled, to
         display OUR messages, in OUR style -->
    <form class="card p-4" novalidate @submit.prevent="send">
      <div class="mb-3">
        <label class="form-label" for="title">Title</label>
        <select id="title" v-model="input.title" class="form-select" :class="{ 'is-invalid': visibleError('title') }">
          <option v-for="t in TITLES" :key="t">{{ t }}</option>
        </select>
      </div>
      <div class="row g-3 mb-3">
        <div class="col-sm-6">
          <label class="form-label" for="firstName">First name</label>
          <!-- @blur: the user leaves the field, which becomes "touched";
               the Bootstrap class is-invalid frames it in red and makes
               the following .invalid-feedback appear -->
          <input id="firstName" v-model="input.firstName" class="form-control"
                 :class="{ 'is-invalid': visibleError('firstName') }" @blur="touched.add('firstName')">
          <div class="invalid-feedback">{{ visibleError('firstName') }}</div>
        </div>
        <div class="col-sm-6">

    • linha 39: os campos que o usuário já deixou. Um [Set] reativo: [touched.add(...)] atualiza a página;
    • linhas 44–57: os erros dos campos, recalculados a cada tecla digitada. Uma string vazia significa “nenhum erro”; [a || b] retorna [b] quando [a] está vazio: isso permite encadear as verificações de um campo, com a primeira que falhar acionando a mensagem;
    • linha 59: verdadeiro se não houver erros;
    • linhas 70–72: o erro de um campo só é exibido se ele foi “tocado” ou após uma tentativa de envio. Um formulário em branco destacado em vermelho antes mesmo de você começar seria desagradável;
    • linha 85: [novalidate] desativa os controles do navegador (atributo [required]...), de modo que apenas nossas mensagens sejam exibidas, em nosso estilo;
    • linha 99: o evento [blur]: o usuário sai do campo;
    • linha 99: a classe [Bootstrap] [is-invalid] contorna o campo em vermelho e exibe o [<div class="invalid-feedback">] que vem em seguida;
    • linha 112: [is-valid], ao contrário, o contorna em verde.

    Uma observação importante: esta validação é apenas uma comodidade. Ela responde imediatamente, sem ida e volta ao servidor, mas não oferece nenhuma proteção: qualquer pessoa pode enviar ao servidor uma requisição montada manualmente (usando o [curl], por exemplo), sem passar por nossas páginas. O servidor deve, portanto, revalidar o que recebe. No Exemplo 20, e mais adiante no estudo de caso, veremos outra abordagem: deixar o servidor cuidar da validação e exibir as mensagens.
